# STEH v1.0.0 — MVP 1.0

Release date: 2026-10-01

## Purpose

`v1.0.0` is the first stable release of the Software Trust Engineering Harness.
It is promoted from `v1.0.0-rc4` without functional changes, after the RC4 release
evidence passed all 30 gates for the 26 acceptance criteria.

## What STEH 1.0 does

STEH turns a software request into a governed engineering workflow in which LLM
agents produce evidence and deterministic gates decide:

- **specification-driven workflow:** requirements, specification with stable
  `FR`/`NFR`/`AC` ids, architecture, STRIDE security review, test plan,
  implementation in an isolated workspace and validation with containerized
  scanners (Semgrep, Gitleaks, Trivy);
- **deterministic policy engine:** quality gates as code decide every
  transition; bounded rework on failed validation; validation fails closed when
  the implementation is missing;
- **human in the loop:** high-risk tasks wait for an authenticated reviewer
  decision and resume from the durable checkpoint exactly once;
- **untrusted-input boundaries:** Context Engine with redaction and budgets;
  read-only, allowlisted GitHub issue analysis and pull-request review;
- **auxiliary LLM-as-Judge:** versioned rubric, never authoritative;
- **asynchronous, recoverable execution:** PostgreSQL job queue and workers,
  `202` + polling API, bounded recovery from LangGraph checkpoints;
- **auditability and observability:** agent runs, audit events, versioned prompts
  with hashes, correlated JSON logs, queue and HTTP metrics, readiness probe.

or API changes.

## Known limitations

- a worker death while recording post-workflow audit events can duplicate some
  `POLICY_DECISION`/`REWORK_DECISION` events (ADR-017);
- the workspace volume is shared per host only; cross-host recovery regenerates
  files through bounded rework;
- queue metrics query PostgreSQL on every scrape;
- STEH 1.0 is not a production security certification.
